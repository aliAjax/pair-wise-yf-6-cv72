# 上门施工放行台（家庭维修事项扩展）

端口规划：`5114`

```bash
npm install
npm run dev
```

## 模块拆分

- `src/model.js` —— 数据模型：事项 / 技师 / 上门单 / 整改项 / 历史记录结构、种子数据、localStorage 读写与 v1→v2 迁移。
- `src/rules.js` —— 规则流转：三道前置放行、技能×两小时时段×同址合并排期、开工检查停止、整改复检释放、完工与退回。
- `src/stats.js` —— 四项统计与阶段筛选。
- `src/components.js` —— 页面组件：只读渲染，动作经 `data-action` 事件委托回入口。
- `src/main.js` —— 入口：加载本地状态、绑定事件、每次变更后持久化（刷新保留）。

## 业务规则

1. **三道前置**：每项维修维护必须完成测量、备料、业主确认；任一未完成不得预约上门，原排期不变，事项旁展示卡点。
2. **排期**：备料等三道齐备后，按技师技能、当日两小时时段（08:00–19:00 共 5 段）、同址合并规则统一安排；同址事项必须由覆盖全部工种的同一技师同一时段承接。任一组冲突即**整次拒绝**，不产生任何排期，候选（技师×时段）顺序保留并展示。
3. **开工前检查**：发现断电、擅自扩项、安全条件不符立即停止，生成整改项；全部整改复检通过才释放原约。
4. **完工**：登记实际费用与业主验收；验收退回转处理中可返工重提；实际费用超承诺两成无论验收结论均转退回处理中。
5. **历史只追加**：事项、上门单、整改项各有 append-only 流转记录。
6. 数据仅存 localStorage，无新增页面、运行时依赖或后端服务。
